## What is Prometheus?
An open-source monitoring and alerting system that stores metrics as time-series data.

---
### 1. What are the Main Components of Prometheus?
The major components of Prometheus are:
- Prometheus Server
- Exporters
- Alertmanager
- Pushgateway
- Service Discovery
- Prometheus TSDB (Time-Series Database)
Together, these components collect, store, query, and alert on monitoring data.

---

### 2. How Does Prometheus Architecture Work?
Prometheus follows a pull-based architecture:  
1. Applications or Exporters expose metrics.
2. Prometheus scrapes metrics from targets.
3. Metrics are stored in the Prometheus TSDB.
4. PromQL is used to query the metrics.
5. Alert rules evaluate metrics against conditions.
6. Alertmanager sends notifications when alerts fire.
---

### 3. What is an Exporter?
A tool that exposes metrics in Prometheus-compatible format.

### 4. What is Node Exporter?
Node Exporter is a Prometheus exporter that exposes Linux operating system metrics such as CPU, memory, disk, filesystem, and network statistics.

Example metrics:
```text
node_cpu_seconds_total
node_memory_MemAvailable_bytes
node_filesystem_avail_bytes
```
---

### 5. What is kube-state-metrics?
kube-state-metrics exposes Kubernetes object states as Prometheus metrics.  
It provides metrics for:
- Pods
- Deployments
- StatefulSets
- ReplicaSets
- Nodes

Example metrics:
```text
kube_pod_status_phase
kube_deployment_status_replicas
```
---

### 6. What is the Difference Between Node Exporter and kube-state-metrics?
- Node Exporter = Infrastructure metrics
- kube-state-metrics = Kubernetes object metrics
---

### 7. What is Alertmanager?
Alertmanager handles alerts generated by Prometheus and sends notifications through multiple channels.

---
### 8. What is a Metric?
A measurable value representing the state of a system.

---
### 9. What are the Metric Types in Prometheus?
Prometheus supports four metric types.

#### Counter
A metric that only increases.

Example: http_requests_total
Typical query: ` rate(http_requests_total[5m]) `

#### Gauge
A metric that can increase or decrease.  
Examples:
- memory_usage
- cpu_usage
- queue_length

#### Histogram
Measures value distribution and request latency.

Example: http_request_duration_seconds  
Commonly used for:
- P95 latency
- P99 latency
- Response time analysis

#### Summary
Measures latency and calculates quantiles on the application side.  
Histogram is generally preferred in distributed environments.  
Example: http_request_duration_seconds

---
### 10. What are Labels?
Key-value pairs attached to metrics used for filtering and aggregation.

### 11. What is Scraping?
The process of collecting metrics from targets.

### 12. What is PromQL?
A query language used to query, aggregate, and analyze metrics stored in Prometheus.

---
### 13. What is a Recording Rule?
A Recording Rule precomputes frequently used or expensive PromQL expressions and stores the result as a new metric.

Example:
```yaml
groups:
  - name: app-rules
    rules:
      - record: job:http_requests:rate5m
        expr: rate(http_requests_total[5m])
```

Benefits:
- Faster dashboard loading
- Reduced Prometheus query load
---

### 14. What are Alerting Rules?
Alerting Rules define conditions under which Prometheus should generate alerts.

Example:
```yaml
groups:
  - name: alerts
    rules:
      - alert: HighCPUUsage
        expr: cpu_usage > 80
        for: 5m
```
The alert triggers when CPU usage remains above 80% for 5 minutes.

---
### 15. What is Retention in Prometheus?
Retention defines how long Prometheus keeps collected metrics before deleting them.

Example: metrics are retained for 15 days.  
```bash
--storage.tsdb.retention.time=15d
```
---

### 16. Why is Prometheus called a Time-Series Database?
Time series: A metric stored over time.  
Because over time it stores:
- Metric
- Timestamp
- Value
---

### 17. How Does Prometheus Store Data?
Prometheus stores data in its built-in Time-Series Database (TSDB).  
Example:
```text
http_requests_total{job="web"} 100
```
---

### 18. What is Federation in Prometheus?
Federation allows one Prometheus server to scrape selected metrics from another Prometheus server.

Common use cases:
- Multi-cluster monitoring
- Large-scale environments
- Centralized monitoring
---

### 19. What is Remote Write?
Remote Write allows Prometheus to send metrics to external storage systems.  
Common examples:  
- Thanos
- Cortex
- Grafana Mimir
- VictoriaMetrics

It is commonly used for long-term metric storage.

---

### 20. What is the Difference Between Federation and Remote Write?

#### Federation
- Prometheus to Prometheus
- Selective metric collection
- Hierarchical monitoring

#### Remote Write
- Prometheus to external storage
- Long-term metric retention
- Large-scale monitoring environments

---
### 21. What is kube-prometheus-stack?
A Helm-based monitoring stack that installs Prometheus, Grafana, Alertmanager, Node Exporter, kube-state-metrics, and Prometheus Operator in Kubernetes.

---

### 22. What is Service Discovery 
Service discovery automatically finds targets from platforms like Kubernetes, AWS EC2, Docker, or Consul so Prometheus can scrape them without manually updating configurations.

Without Service Discovery Problem:  
New servers require manual updates. Scaling is difficult  
Kubernetes pods change IPs frequently

With Service Discovery  
Prometheus automatically discovers targets.
Example:
```
scrape_configs:
  - job_name: kubernetes-pods
    kubernetes_sd_configs:
      - role: pod
```
Prometheus continuously asks Kubernetes: Show me all pods exposing metrics and automatically updates targets.

---

### 23. What is ServiceMonitor?
ServiceMonitor is a Kubernetes Custom Resource (CRD) created by Prometheus Operator that defines how Prometheus should discover and scrape Kubernetes Services.
It defines:
Which Service should be monitored  
Which port should be scraped  
How frequently it should be scraped  

Example ServiceMonitor:
```
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: my-app-monitor
spec:
  selector:
    matchLabels:
      app: my-app

  endpoints:
  - port: http
    interval: 30s
```
Meaning: 
Find Service with label app=my-app
Scrape every 30 seconds

### 26. What is Grafana?

Grafana reads data from multiple sources and presents it through visual dashboards.

---

### How Do You Create Alerts in Grafana?

Steps:
1. Create a metric query.
2. Define alert conditions.
3. Configure threshold values.
4. Configure notification channels.
5. Save the alert rule.
Grafana continuously evaluates the defined conditions and sends notifications when thresholds are breached.

---

### What is Prometheus Federation vs Remote Storage Architecture?
Federation is used when multiple Prometheus servers exchange selected metrics for centralized monitoring.  
Remote Storage (Remote Write) is used when metrics need to be stored externally for long-term retention and scalability.  
Example:

```text
Federation:
Prometheus A --> Prometheus B

Remote Write:
Prometheus --> Thanos / Mimir / Cortex
```

---

### Why Are Histograms Preferred Over Summaries?

Histograms are generally preferred because:

- Quantiles can be calculated centrally in Prometheus.
- Data can be aggregated across multiple instances.
- Better suited for distributed systems.

Summaries calculate quantiles on the client side and cannot be efficiently aggregated across instances.

## Push vs Pull
### Pull
Prometheus --> Target  

Advantages:
Target health checking  
Better scalability  
Simpler configuration  

### Push
Application --> Monitoring Tool

Examples:
CloudWatch, 
Datadog Agent

---

###  Explain the difference way in which prometheus can get metrics ?
Prometheus supports two metric collection models: pull-based and push-based. In our organization, most metrics are collected using the pull model, where applications expose a /metrics endpoint and Prometheus scrapes it at regular intervals.Developers expose the required application metrics, and Prometheus is configured to discover and scrape those targets.  
For short-lived jobs such as batch jobs or temporary containers, we use Pushgateway, where applications push metrics before terminating. Pull-based collection is generally preferred because it is simpler, more reliable, and allows Prometheus to detect target availability.
